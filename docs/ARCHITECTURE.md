# Architecture and delivery boundaries

Implemented: React/TypeScript/Vite, same-origin FastAPI, Pydantic request/extraction schemas, SQLAlchemy + Alembic on PostgreSQL 17, private S3-compatible object adapter, separate same-codebase worker with SQL durable queue, leased `SKIP LOCKED` claims, retries and atomic fact/page/job commits. Disk-backed S3rver is the loopback synthetic emulator because MinIO images were unavailable. Its default dev credentials and network binding are not production access controls.

Domain persistence uses a **compact tenant-scoped JSON domain record table**, not the blueprint's fully normalized entity model. Projects, tags, immutable-by-API document versions/pages, accepted fact revisions, fact review history, evaluations, adjudications, commercial versions, management decisions and audit events are persisted. Composite foreign keys constrain tenant/project and tenant/document relations. Sessions are server-side records with opaque hashed cookie identifiers, CSRF tokens, expiry/revocation. Object authorization checks both tenant and explicit project membership on every data endpoint, including jobs, downloads and exports. Demo Alice/Bob have distinct project memberships in one tenant; outsider is another tenant. Viewer mutations are denied.

Source uploads always create new UUID/object keys and preserve SHA-256 originals. Unsupported relevant files stay in the manifest as gaps. Parser subprocess has CPU/address-space limits and a wall timeout; extraction schema checks fields, page/line bounds and exact quote/value correspondence. Documents cannot supply executable rules or invoke tools. PDF physical pages and TXT one-based lines are retained. OCR is absent and unreadable pages block GO. Normalization preserves unknown units rather than guessing gpm, pressure basis or material compatibility.

Synthetic pack `synthetic-demo-v1` requires eight positive checks (flow, head, fictional liquid/material/approval/NPSH datum, explicit prohibition status and action status). Numeric ranges are invented **training-only** limits, not portfolio evidence. A capability check outside the fictional scope returns FAIL at rule level but INSUFFICIENT DATA at tag level, since no complete approved alternative scope exists. Only an accepted `confirmed-demo-ban` prohibition yields NO-GO. Unknowns remain in reports even when a hard prohibition dominates. Noncritical explicit actions yield CONDITIONAL GO. Empty/unreviewed/conflicting facts, draft rules, absent approvals and document coverage gaps prevent GO. All results retain rule hashes and fact references. Complete-package tag precedence is NO-GO → INSUFFICIENT DATA → CONDITIONAL GO → GO. Live evaluations are disabled, not silently evaluated using the demo pack.

Frozen reports contain requirements, raw/normalized values, human fact reviews, document hashes, rule authority and fictional capability evidence, versions, findings, clarifications and run hash. Post-run dispositions are append-only **outside** the frozen export; the report states that boundary. Read them in History. Full signed review annex export is pending. Commercial snapshot is labelled manual and never changes technical logic. Pressure/head and SI power helpers are implemented and independently tested; no motor/hydraulic selection is inferred.

## Remaining Phase 1 / production gaps

- Managed OIDC adapter (Authlib code+PKCE/state/nonce/session) is implemented but not verified against a real provider. Local demo identities are intentionally not corporate authentication. Configure subject-bound invitations before provider testing. Project-member administration and full Admin/Commercial role UI remain pending.
- Real LLM adapter has mocked citation-rejection tests only; extraction quality, budgets/token accounting and approval of provider data processing remain unverified. It is off by default. Demo parser covers documented fixtures, not arbitrary tables or all blueprint fields/modality/editions.
- No approved live KSB rules, portfolio capability/approval records, engineering precedence matrix or customer data. No hydraulic selection, compatibility, curves, OCR, pricing, corporate integration, or certification.
- Rule pack is versioned/hashed in code, using allowlisted range/enum checks; full externally submitted typed JSON contract, margin/approval-record operators, controlled publication/engineering approval UI, expiry and capability registries remain pending. No live rules can be published through this prototype.
- Partial-lot selection, exhaustive approved portfolio failure, owned clarification/deviation lifecycle, document revision precedence, deletion/legal hold and retention automation are pending. The current UI supports complete-package scope only.
- Full normalized UUID entity schema, database-enforced append-only protection/RLS, structured source-span search, cursor pagination, generated OpenAPI client and richer error envelopes are pending. The current client has explicit TypeScript contracts and the API exposes OpenAPI.
- Ingestion fails closed outside demo mode until malware scanning is integrated. Demo uses EICAR marker detection only. Parser resource limits are not a complete network-isolated sandbox. Distributed cancellation, continuous heartbeats during arbitrary long work, orphan object reconciliation and large-file/load testing remain pending. The bounded parser/LLM stages renew the lease between stages.
- Downloads use a membership-checked authenticated proxy rather than presigned external URLs. Production S3 IAM/encryption/TLS, managed DB least privilege, secrets manager, provider allowlists, MFA, security review, operational backup/restore and incident controls remain release gates.
- Local S3rver dependencies have npm advisories (3 high, 1 moderate in the initial audit). It is a loopback synthetic emulator with no public ingress; replace it with an approved private object service before any real usage. UI tooling/runtime audit is clean after updating Vite and Playwright. No claim of a production security audit.
