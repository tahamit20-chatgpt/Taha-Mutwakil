# Three separate standards layers

A: suggested references use product context and, where relevant, customer profile. Market area alone does not establish obligation. Suggestions remain nonmandatory until engineer-confirmed.

B: explicit RFQ references are parsed with document/physical page/line/worksheet/cell/paragraph, raw source text, tag and stated edition. Contradictory editions remain visible; newest upload is never automatic precedence. Unstated edition remains null.

C: approved versioned rules have separate authority/capability references. The bundled identifiers (API 610, ISO 13709, ISO 5199, ISO 2858, ASME B73.1, API 682, customer/HI/9COM reference categories) include no licensed clause text or real KSB engineering thresholds. Unavailable standards show REFERENCE NOT AVAILABLE / REQUIRES REVIEW. Even a synthetic clause check cannot imply blanket full-standard compliance.

Registry additions require configuration permission; applicability decisions require project membership, engineer role, explicit reason and expected project revision. Rule publication requires separate designated permission. Technical meaning cannot be granted by merely adding a standard's name.
